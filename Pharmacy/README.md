# ОАО «Жар-птица»

Приложение для варианта В5_КОД 09.02.07-2-2026-БУ. C# / WPF / .NET 10, SQLite. Исходный проект криптобиржи в родительской папке сохранён.

## Запуск

Откройте `run.cmd` в этой папке. Готовая сборка: `Deliverable/ZharPtitsa.exe`. EXE ищет .NET также в `../../.dotnet`; при переносе на другой компьютер установите .NET Desktop Runtime 10 x64. Для сборки выполните `powershell -ExecutionPolicy Bypass -File Pharmacy/build.ps1` из родительской папки.

Список учётных записей взят из исходного файла:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Пользователь | ivanov_ps | user123 |
| Менеджер | manager | manager123 |
| Администратор | admin | admin123 |

Также перенесены остальные пять учётных записей. Пароли в рабочей базе хранятся как PBKDF2-SHA256 с индивидуальной солью, 100 000 итераций. Исходные учебные пароли остаются в предоставленном файле импорта.

## Возможности

- Гость: каталог, поиск по всем текстовым полям, фильтр по типу, сортировка по конечной цене, подробная информация, переход ко входу.
- Пользователь: корзина, добавление и удаление единицы товара, оформление всей корзины с адресом доставки.
- Менеджер: добавление, изменение и удаление продукции; просмотр заказов.
- Администратор: управление продукцией и заказами, включая состав заказа.
- Выход очищает корзину и возвращает гостевой режим. ФИО и роль расположены справа вверху.
- Поиск по нескольким словам работает совместно с фильтром и сортировкой без кнопки запуска. Состояние сохраняется после изменения продукции.
- Фото выбирается размером не более 300 × 200 пикселей, сохраняется в `Deliverable/Images`. Старое неиспользуемое фото удаляется. Редактор открывается модально, одновременно доступно только одно окно.
- Цвета: белый, #D2DFFF, #355CBD; действующая скидка свыше 10% — #BB5FCA. Шрифт Candara, оригинальные логотип и иконка.

## База и импорт

`Database.sql` — схема; `DatabaseWithData.sql` — полный скрипт со всеми импортированными данными; `Deliverable/pharmacy.db` — готовая SQLite-база. Схема включает Roles, Users, ProductTypes, Products, OrderStatuses, Orders, OrderItems. Денежные значения хранятся в целых копейках, итог позиции и заказа вычисляется. Ссылочная целостность включена в каждом соединении.

При первом запуске пустая база создаётся автоматически. `Import/PrepareImport.ps1` повторно подготавливает `seed.json` из исходного XLSX без Excel. Приложение импортирует JSON одной транзакцией. Повторный запуск не дублирует импорт. Восстановление из `DatabaseWithData.sql` выполняется в новую пустую базу SQLite.

Особенности исходных данных:

- В XLSX 8 пользователей, 15 товаров и 12 строк позиций, образующих 7 заказов. Номера заказов отсутствуют: строки группируются по адресу, логину, статусу и обеим датам.
- PNG-пути сопоставлены с реальными JPG по имени без расширения. Пустые пути и отсутствующий `panthenol.png` дают `picture.png`. Для пустых путей фото не назначались произвольно.
- Дробные числа исходного файла округлены до копеек. Суммы всех строк сверены с количеством и ценой.
- Импорт исторических заказов не меняет исходные остатки. Оформление покупателем уменьшает остатки в одной транзакции. При административном изменении исторического заказа склад не пересчитывается; это явно указано в форме.
- Товар из истории заказов нельзя удалить: приложение показывает объяснение, внешний ключ дополнительно защищает данные.

## Материалы для сдачи

- Исходный код: `Program.cs`, `Sqlite.cs`, `Store.cs`, `OrdersWindow.cs`, `Checks.cs`, `Pharmacy.csproj`.
- Исполняемые файлы и база: папка `Deliverable` целиком.
- Полный SQL-скрипт: `DatabaseWithData.sql`.
- ER-диаграмма с атрибутами, ключами и связями: `Documentation/ER-diagram.pdf`.
- Блок-схема по обозначениям ГОСТ 19.701-90: `Documentation/Algorithm.pdf`.
- Отчёт с шестью снимками интерфейса: `Documentation/Verification.docx`.
- Протокол автоматических проверок: `Deliverable/checks.txt`.

`--check` выполняет проверки на отдельной временной БД. `--capture` создаёт снимки WPF-интерфейса в `captures` без оформления заказов и изменения исходных данных. Скрипт `Documentation/build_documents.py` создаёт схемы и отчёт; для него нужны Python, reportlab и python-docx.

Репозиторий проекта: https://github.com/qsrebokser-cloud/pharmacy. Материалы размещены в папке Pharmacy: исходники, Deliverable, SQL и Documentation.
